# 医療情報ウォッチ（COLLECTA・v3.7.5・PoC）

薬局・クリニック向けの規制/臨床情報 収集・重要度判定ツール。
[Pharmacy OS](https://github.com/fleezappm-ux/pharmacy-os) からは完全に独立して動作する。

## 現在の状態（このコミット）

### 実装済み

- **PMDA回収情報**の取得（年度・クラスごとのCSV、クラスI・II・IIIをそれぞれ独立した情報源として取得。年度は日付から自動算出）
- **厚生労働省 医療用医薬品供給状況**の取得（限定出荷・供給停止・供給再開の検知を含む）
- **Mindsガイドラインライブラリ「お知らせ」**の取得（v3.3で追加。タイトルに「ガイドライン」を含むものだけを対象に、治療・臨床ウォッチ（clinical）へ計上。重要度は一律「info」からスタートし、人間が個別確認する運用）
- **学会お知らせ（日本内科学会・日本糖尿病学会）**の取得（v3.4で追加。タイトルに「ガイドライン」「指針」「ステートメント」等のキーワードを含むものだけを対象に、治療・臨床ウォッチ（clinical）へ計上。重要度は一律「info」からスタートし、人間が個別確認する運用）
- **厚労省報道発表（薬機法等の法的関連情報）**の取得（v3.5で追加。厚労省の報道発表資料月別一覧のうち、タイトルに「薬機法」「医薬品」「薬事」等のキーワードを含むものだけを対象に、行政通知として計上。重要度は一律「info」からスタートし、人間が個別確認する運用）
- **沢井製薬お知らせ**の取得（v3.6で追加。供給関連・回収情報のお知らせだけを対象）
- **日医工お知らせ**の取得（v3.7で追加。供給関連・回収情報のお知らせだけを対象）
- 毎朝7時台の**自動取得トリガー**（GAS）
- 確認状態・重要度確定・HOME表示確定・ウォッチ設定の**永続化**（Googleスプレッドシート・PropertiesService）
- **情報源ごとの取得成功/失敗を分離管理**し、一方が失敗しても他方・失敗側の既存情報を消さない
- **内容変更のハッシュ検知（SHA-256）**：内容が変わった情報は人間の再確認状態へ自動的に戻す（HOME表示は維持しつつ「再確認必要」フラグを立てる）
- **供給再開・限定出荷解除の検知**：Excelで明示的に「通常出荷」を確認できた場合だけ解消と判定する。単にExcelから品目が消えただけの場合は「掲載未確認（要手動確認）」として扱い、内容・HOME表示は前回のまま維持する（誤って供給再開扱いにしない）
- **再確認フラグの解除条件を限定**：「内容を確認済みにする」を明示的に行った場合のみ解除される。GAS側でも、再確認が必要な情報は先に確認済みにしないと重要度・HOME表示の変更を受け付けない
- **ウォッチ設定IDの固定許可リスト**：初回保存前でも任意のIDを保存できないよう、GAS側に固定リストを持たせている
- GAS側の**排他制御（LockService）**：自動取得と人間の操作が同時に走っても確認状態が失われない。外部への取得はロックの外で行い、シート更新の直前にロックを取って最新状態を読み直す構成
- GAS側の**入力値検証**：`doPost`はホワイトリスト方式で値を検証し、対象外(excluded)情報の変更・重要度未確定でのHOME表示ONなどの業務ルールをサーバー側でも強制
- **変更履歴のUI表示**：情報の詳細画面に「変更履歴」セクションを追加し、information_item_historyに記録された変更（変更前後の内容）を新しい順に表示できるようにした
- **GitHub Pages公開済み**：https://fleezappm-ux.github.io/medical-info-watch/
- **実データ読み込み中の表示**（v3.4で追加）：ページを開いた瞬間の自動読み込み中に何も表示が無く「固まっているように見える」問題を修正。読み込み中は「実データを読み込み中…」と表示するようにした
- **COLLECTAブランディング・PWA化**：favicon・アプリアイコン（apple-touch-icon、maskable含む）・`manifest.webmanifest`を追加し、対応ブラウザで「ホーム画面に追加」「アプリをインストール」からCOLLECTAのアイコン・名前でホーム画面/デスクトップに追加できるようにした。ヘッダーにCOLLECTA起動ボタンを追加し、埋め込み表示（Pharmacy OS/Notion等）から本当のブラウザタブへ開き直せるようにした
- **カテゴリ（項目）・情報源フィルタ**：情報一覧を業務カテゴリ（薬局業務／クリニック業務／治療・臨床／医療システム）・情報源で絞り込めるようにした。カテゴリ「すべて」選択時は自動的にカテゴリ別グループ表示になる。既存の状態タブ（全件一覧／要確認／変更あり／重要情報確定／取得エラー）と組み合わせ可能。※チャッピー監査（v3.7.5時点）で「操作方法が複雑すぎる」「業務画面としての再設計が必要」との指摘あり、次段階で見直し予定

### 現在のセキュリティレベル（重要）

このアプリは現在、**認証未実装のPoC**です。GASのWeb Appは「アクセスできるユーザー：全員」で公開されており、**API URLを知っている人なら誰でも確認状態・重要度・ウォッチ設定を書き換えられます**。入力値の形式検証・業務ルールのチェックはサーバー側（GAS）に追加済みですが、これは「不正な値を弾く」ためのものであり、「本人確認をする」ものではありません。

本番運用の前には、認証付き中継バックエンドまたは共通ログイン基盤の導入が必須の課題として残っています。

### 現在取得している情報範囲

- PMDA回収情報：**2026年度（該当データが無ければ前年度）のクラスI・II・III**。クラスごとに別の情報源として取得成功/失敗を分離管理。idは常に「pmda_recall_ + 回収番号」（v3.2.1で修正、クラスをまたいでも一意）
- 厚労省供給状況：限定出荷・供給停止・供給再開（一覧には出さないが変更として検知）のみ。それ以外の通常出荷品目は表示しない
- Mindsガイドラインライブラリ：お知らせ一覧の1ページ目（最新10件程度）のうち、タイトルに「ガイドライン」を含むものだけ
- 学会お知らせ：日本内科学会（最新20件まで）・日本糖尿病学会（最新30件まで）のお知らせ一覧のうち、タイトルに合意済みキーワード（ガイドライン・指針・ステートメント等）を含むものだけ
- 厚労省報道発表：報道発表資料の月別一覧（当月・前月）のうち、タイトルに合意済みキーワード（薬機法・医薬品・薬事・薬局等）を含むものだけ
- 沢井製薬お知らせ：トップページ掲載のお知らせのうち、供給関連カテゴリと回収情報セクションのお知らせだけ
- 日医工お知らせ：年別お知らせ一覧のうち、タイトルに合意済みキーワード（限定出荷・出荷停止・自主回収等）を含むものだけ
- **日本糖尿病学会は現在保留中**：v3.7.1〜v3.7.4で原因切り分けを行った結果、お知らせモジュールだけがGASからのアクセスを一律拒否しており、GAS側で回避する方法が見つからなかったため、v3.7.5より自動取得から外している（詳細は`gas/README.md`参照）

## GASの設定・移行について

`gas/pmda-recall-fetcher.gs` をGoogle Apps Scriptへ貼り付けて使う。既存のスプレッドシートに旧バージョン（v2）の「情報アイテム変換結果」シートがある場合、初回の `runConvertAllToInformationItems` 実行時に自動的に新しい `information_items` シートへ移行される（旧シートは削除されず「旧_情報アイテム変換結果」という名前で残る）。詳細は `gas/README.md` を参照。

## GitHub Pagesへのデプロイ

`main` ブランチへのpushで `.github/workflows/deploy.yml` が自動的にビルド・デプロイする。公開URL：https://fleezappm-ux.github.io/medical-info-watch/
